# مواصفة التصميم: إضافة كروم "Grouping Tabs" — وكيل متصفح في Side Panel

التاريخ: 2026-11-13
الحالة: مكتملة — بانتظار المراجعة

## 1. الهدف

إضافة كروم (Manifest V3) تعرض لوحة شات جانبية (side panel) فيها وكيل ذكاء اصطناعي يتحكم في المتصفح — خصوصاً التبويب النشط — لتنفيذ: إملاء الحقول، تلخيص المقالات، السؤال عن كود الموقع المفتوح، البحث عن الأسعار في مواقع خارجية، وإدارة التبويبات/الجروبات/الجلسات.

**قيد صارم: بدون backend.** كل شيء يعمل داخل الإضافة؛ الاتصال الخارجي الوحيد هو fetch مباشر من service worker إلى مزود LLM متوافق مع OpenAI (base URL + API key يوفرهما المستخدم).

## 2. القرارات المعتمدة

| القرار | الاختيار |
|---|---|
| المزود | OpenAI-compatible API فقط (سحابي) — يُسحب قائمة النماذج من `/v1/models` ويختار المستخدم |
| الواجهة | Svelte 5 (runes) في side panel |
| عارض Markdown المتدفق | Flowdown (`@localix-ai/flowdown`) — تحليل تزايدي O(1)، بدون تبعيات، MIT |
| عميل LLM | AI SDK 5 (`@ai-sdk/openai-compatible`) داخل service worker |
| البناء | Vite + CRXJS (يدعم Vite 8) |
| تلوين الكود | highlight.js (مبسط) عبر callback تلوين Flowdown |
| الصلاحيات | موافقة على الإجراءات الحساسة فقط |
| لغة الواجهة | عربي/إنجليزي قابلة للتبديل (i18n) |
| النطاق | كل الميزات من البداية (MVP كامل) |

## 3. المعمارية

```
grouping-tabs/
├── manifest.json              (MV3 عبر CRXJS)
├── src/
│   ├── background/            ← Service Worker
│   │   ├── agent.ts           حلقة الوكيل (LLM → tool calls → تنفيذ → رد)
│   │   ├── llm.ts             AI SDK: streaming + function calling + /models
│   │   ├── tools/             أداة لكل ملف بنمط MCP
│   │   ├── skills.ts          تحميل/تشغيل/حفظ ملفات JSON للمهارات
│   │   └── sessions.ts        الجلسات في chrome.storage.local
│   ├── sidepanel/             ← Svelte 5
│   │   ├── App.svelte / Chat / SessionList / ApprovalCard / Settings
│   │   └── markdown.ts        ربط Flowdown (mount API) لعرض الرسائل
│   ├── content/               content script يُحقن عند الطلب (قراءة/ملء/نقر)
│   └── shared/                أنواع TypeScript، i18n، مخطط الأدوات
└── vite.config.ts
```

### تدفق الأمر
1. رسالة من side panel → service worker مع سياق التاب النشط.
2. الـ agent يبني الطلب للـ LLM مع تعريفات الأدوات (function calling).
3. عند استدعاء أداة: تنفيذ محلي (chrome APIs أو حقن content script أو CDP).
4. الإجراءات الحساسة تظهر بطاقة موافقة/رفض في الـ panel قبل التنفيذ؛ الرفض يعود للوكيل كنتيجة أداة فشلت.
5. النتائج تعود للـ LLM → رد متدفق (SSE) يعرض في الـ panel عبر Flowdown.

### الصلاحيات المطلوبة
`tabs`, `tabGroups`, `storage`, `scripting`, `debugger`, `sidePanel`, `host_permissions: <all_urls>` — للقراءة والتحكم فقط.

## 4. الأدوات (بنمط MCP)

كل أداة: `name` + `description` + `inputSchema` (JSON Schema) + `handler`. الشكل يطابق أدوات MCP لتمكين عرضها لوكيل خارجي لاحقاً (اتجاه mcp-chrome) دون إعادة بناء.

### أدوات الصفحة
| الأداة | الوظيفة | حساسة؟ |
|---|---|---|
| `read_page` | استخراج نص + عناصر تفاعلية (حقول/أزرار بعناوين) | لا |
| `summarize_page` | تلخيص المقال الحالي | لا |
| `inspect_code` | قراءة DOM والسكربتات وأخطاء console وطلبات الشبكة عبر `chrome.debugger` (CDP) | لا (قراءة) |
| `fill_fields` | ملء الحقول بقيم محددة | نعم |
| `click_element` | النقر على عنصر بعنوانه | نعم |
| `screenshot` | لقطة للتبويب النشط | لا |

### أدوات التنقل
| الأداة | الوظيفة | حساسة؟ |
|---|---|---|
| `navigate` | انتقال التاب النشط لرابط | نعم |
| `open_tab` / `close_tab` | فتح/إغلاق تبويبات | نعم |
| `list_tabs` | كل التبويبات والجروبات | لا |

(بحث الأسعار = حلقة `navigate` → `read_page` → استخراج → رد.)

### أدوات التبويبات
| الأداة | الوظيفة | حساسة؟ |
|---|---|---|
| `group_tabs` | تجميع التبويبات غير المجموعة في جروبات (تسمية بالـ LLM حسب الموضوع/النطاق) | لا |

### أدوات المهارات (Skills/Plugins)
| الأداة | الوظيفة | حساسة؟ |
|---|---|---|
| `run_skill` | تنفيذ مهارة محفوظة بالاسم + parameters | تتبع حساسية خطواتها |
| `save_skill` | تحويل إجراء من المحادثة إلى ملف JSON وحفظه | لا |
| `list_skills` / `delete_skill` | عرض/حذف المهارات | لا |

### الجلسات (الشات)
جلسات متعددة بأسماء تُحفظ في `chrome.storage.local` مع تبديل من قائمة الـ panel.

## 5. نظام المهارات (Skills)

كل مهارة = ملف JSON واحد (قابل للتصدير/الاستيراد) يصف خطوات أتمتة حتمية بأدوات موجودة:

```json
{
  "name": "check-oneplus-price",
  "description": "يفحص أسعار إصدارات OnePlus في موقع X",
  "params": [{ "name": "model", "type": "string", "required": true }],
  "steps": [
    { "tool": "navigate", "args": { "url": "https://example.com/search?q=oneplus {{model}}" } },
    { "tool": "read_page", "args": {} },
    { "tool": "click_element", "args": { "label": "Add to cart" }, "approval": true }
  ]
}
```

- الخطوات حتمية: أداة + وسائط ثابتة + متغيرات `{{param}}` من الطلب.
- `approval: true` على الخطوة = بوابة موافقة حتى لو كانت الأداة غير حساسة.
- **مسارا الإنشاء**: (أ) المستخدم يكتب JSON يدوياً، (ب) الوكيل يحوّل خطوات محادثة عادية إلى مهارة عند طلب "احفظ هذا كـ skill باسم X" — يستخرج تسلسل الأدوات المنفذة ويقترحه للتأكيد قبل الحفظ.
- الاستدعاء بالاسم: المستخدم يكتب "شغّل check-oneplus-price" أو الوكيل يتعرف على النية.

## 6. الإعدادات

صفحة options (أو تبويب داخل الـ panel): Base URL + API key → زر "جلب النماذج" (`GET /v1/models`) → اختيار النموذج الافتراضي + اللغة. التخزين في `chrome.storage.local` — المفتاح لا يغادر الجهاز إلا للمزود.

## 7. معالجة الأخطاء

- فشل/انقطاع البث → رسالة في الشات + زر إعادة محاولة لنفس الرسالة (بدون فقدان السياق).
- رفض `chrome.debugger` (صفحات chrome:// وغيرها) → خطأ مترجم للوكيل يرد به للمستخدم.
- فقدان الحقن (إعادة تحميل الصفحة) → إعادة حقن تلقائية قبل أدوات الصفحة.
- 429/5xx → إعادة محاولة بتراجع أسي (3 مرات) ثم إظهار الخطأ.

## 8. الأمان

- تعقيم HTML في العرض (Flowdown يتعقّم الروابط افتراضياً).
- لا إجراء حساس بدون موافقة صريحة.
- المفتاح في `chrome.storage.local` فقط.

## 9. الاختبار

- Vitest: حلقة الوكيل مع LLM وهمي + التحقق من مخططات الأدوات + محرك قوالب `{{param}}`.
- فحص يدوي: ملء نموذج، تلخيص مقال، سؤال عن كود صفحة، بحث سعر، تجميع تبويبات، حفظ/استرجاع جلسة، إنشاء/تشغيل مهارة، موافقة/رفض إجراء حساس، تبديل اللغة.
